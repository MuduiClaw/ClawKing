# 安装后第一步

> 这篇写给刚跑完 `setup.sh` 的人。
> 目标不是讲全，而是让你在前 10 分钟内把系统真正用起来。

如果你还没安装，先回到 [README](../README.md)。
如果你正在准备 API Key、频道、搜索或 Tailscale，细节看 [配置指南](SETUP-GUIDE.md)。

---

## 先记住一件事

ClawKing 装完不是“可以聊天”就结束了。

真正决定体验的，是这三件事：

1. **系统是否真的在跑**
2. **AI 是否拿到了正确的配置**
3. **你的 workspace 是否写出了清晰的人格、用户画像和工作规则**

这篇就按这个顺序来。

---

## 前 10 分钟路线图

| 时间 | 你要做什么 | 完成标志 |
|------|-----------|---------|
| 第 0-2 分钟 | 验证安装 | `openclaw status` 正常，Dashboard 能打开 |
| 第 2-4 分钟 | 配置默认模型 | 至少有一个可用模型认证完成 |
| 第 4-6 分钟 | 定义你的 AI | 改完 `SOUL.md`、`USER.md` 的最小版本 |
| 第 6-7 分钟 | 发起第一次对话 | 能在网页或聊天频道里完成一轮真实对话 |
| 第 7-8 分钟 | 连接一个频道 | Discord / 飞书 / 其他频道至少通一个 |
| 第 8-9 分钟 | 登录一个 coding agent | `codex`、`claude` 或 `gemini` 至少一个可用 |
| 第 9-10 分钟 | 选下一步方向 | 知道接下来该看哪篇文档 |

如果你只做前三步，系统已经可以稳定开始工作。

## 第一步：验证安装

先确认不是“脚本跑完了”，而是“服务真的起来了”。

### 1.1 看总状态

```bash
openclaw status
```

你要关注的不是所有细节，而是：

- Gateway 在运行
- Dashboard 在运行
- 没有明显的 failed / stopped 状态

如果这里已经报错，先不要往后配人格和频道，直接去看 [TROUBLESHOOTING](TROUBLESHOOTING.md)。

### 1.2 打开 Dashboard

浏览器访问：

```text
http://localhost:3001
```

如果你只想用命令行快速测通：

```bash
curl -I http://localhost:3001
```

返回 `200` 或能正常打开页面，就说明监控面板在线。

### 1.3 可选：顺手看一下对话入口

```text
http://localhost:3456
```

这是 Control UI。
如果你暂时还没准备好聊天频道，也可以先用它完成第一次对话。

## 第二步：配置 AI Key / 默认模型

安装向导通常已经带你走过一轮。
但只要模型认证没完成，后面所有步骤都会像“系统装好了但不会动”。

### 2.1 如果你还没配好

运行：

```bash
openclaw configure
```

优先完成：

- 默认模型
- 对应认证方式
- 必要时的搜索配置

详细分支不要在这里看，直接跳到 [配置指南](SETUP-GUIDE.md)：

- [LLM 模型配置](SETUP-GUIDE.md#llm-模型配置)
- [聊天频道配置](SETUP-GUIDE.md#聊天频道配置)
- [Web 搜索](SETUP-GUIDE.md#web-搜索可选)

### 2.2 选型建议

如果你只想先跑通，不想现在研究模型策略：

- 日常对话：先用安装时选的默认模型
- 代码任务：后面补一个 coding agent
- 搜索：没有明确需求可以先跳过

重点不是一开始就“最强配置”，而是先有一个稳定可用的默认路径。

## 第三步：定义你的 AI

这一步决定它像不像你的搭档，而不是随机一个会说话的模型。

先打开 `~/clawd/`，只改最关键的两个文件：

- `SOUL.md`
- `USER.md`

如果你愿意，再补 `IDENTITY.md`。

### 3.1 `SOUL.md` 先写最小版本

最小可用只需要回答三件事：

- 它是谁
- 它服务什么目标
- 它做事时遵循什么原则

你不用写长篇宣言。
写清楚，比写漂亮更重要。

示例思路：

```markdown
- 我是：你的 AI 合伙人
- 服务目标：帮你推进产品、代码和日常协作
- 协作模式：默认行动，关键风险先确认
```

### 3.2 `USER.md` 写你的真实偏好

这一步常被跳过，但影响非常大。

至少写清楚：

- 你是谁
- 你最近在做什么
- 你如何判断一个建议值不值得做
- 你讨厌什么样的回答

比如：

```markdown
- 沟通风格：直接，不要铺垫
- 产出偏好：正确 > 完整 > 速度
- 厌恶：没有结论的长解释
```

### 3.3 想继续深入，再看这两篇

- [WORKSPACE.md](WORKSPACE.md) 讲清楚 `~/clawd` 每个核心文件分别负责什么
- [MEMORY.md](MEMORY.md) 讲清楚长期记忆怎么组织

---

## 第四步：做第一次真实对话

不要用“你好”“在吗”这种测试语句。

第一次对话最好就让系统做一件真实的小事，这样你能同时验证：

- 模型是否可用
- 人格是否起作用
- 输出格式是否符合你的偏好
- 系统有没有读到 workspace

### 推荐的第一句

你可以直接复制下面任意一句：

> 先根据当前 workspace 总结一下你是谁、我的目标是什么、你接下来默认会怎么和我协作。

> 先不要做任务，先给我一份 5 条以内的“你理解的工作方式”，如果哪里理解错了我来纠正。

> 结合 `SOUL.md` 和 `USER.md`，给我一个你今后回复我时应该遵循的简版行为准则。

### 用哪里聊都可以

- 用 Control UI：适合快速验证
- 用 Discord / 飞书：适合直接进入日常使用

如果它的理解明显不对，不要忍着继续用。

立刻回去改：

- `SOUL.md`
- `USER.md`
- 必要时 `IDENTITY.md`

这比后面抱怨“AI 怎么总不懂我”便宜得多。

## 第五步：连接一个聊天频道

如果你只用网页界面，系统当然也能工作。
但 ClawKing 的自然用法通常是“住进你已经在用的聊天入口”。

### 最快的两条路

- Discord：最适合个人和开发者日常协作
- 飞书：最适合团队聊天和办公环境

### 你现在该看哪篇

- 总览先看 [频道配置大全](guides/channels-overview.md)
- 如果你就想先跑通 Discord，直接看 [Discord 指南](guides/discord.md)

### 判断是否真的配好了

不是“配置写进去了”，而是：

- 你给 Bot 发第一条消息
- 它能回
- 群聊 / 线程 / DM 的行为符合你的预期

如果你要接更多频道，不要在这一步把所有平台一次性全上。
先把一个频道跑顺，再扩。

## 第六步：登录一个 coding agent

ClawKing 能调度编码代理，但前提是你至少登录一个。

三选一即可：

```bash
codex
claude
gemini
```

首次运行按提示登录。

### 先装哪个

如果你只想先有一个稳定选择：

- 偏执行：看 [Codex 指南](guides/codex.md)
- 偏复杂推理：看 [Claude Code 指南](guides/claude-code.md)
- 偏长上下文 / Google 生态：看 [Gemini CLI 指南](guides/gemini.md)

### 现在不用做的事

你不需要一开始把三个都调到最优。

先做到：

- 至少一个 agent 能正常启动
- 你知道它的认证方式
- 你知道该从哪篇指南继续看

就够了。

## 新用户最容易踩的 6 个坑

### 1. 装完就开始堆功能

错。
先验证服务、模型、workspace，再扩展频道和工具。

### 2. 跳过 `USER.md`

这样你得到的通常只是一个通用助手，而不是“懂你怎么做事”的搭档。

### 3. 第一次对话只发“你好”

这几乎测不出任何真实问题。
第一轮就让它做一个真实的小任务。

### 4. 一口气接 4 个频道

排查问题会非常痛苦。
先跑通一个，再复制经验。

### 5. 把 setup 细节和日常使用混在一起

安装细节去看 [SETUP-GUIDE](SETUP-GUIDE.md)。
这篇只负责“装完之后先做什么”。

### 6. 没有登录 coding agent 就直接要求它改代码

ClawKing 可以调度编码代理，但代理本身必须先完成首次登录。
